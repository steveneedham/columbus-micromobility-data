PYTHON SCRIPTS
==============

File: /mnt/project/scripts/pull_311.py
Environment: Python 3.11 (invoked by GitHub Actions or local)
Purpose: Fetch Columbus 311 complaints from GIS REST API
API Endpoint: https://maps2.columbus.gov/arcgis/rest/services/Applications/ServiceRequests/MapServer/0/query
Auth: None (public read-only)
Timeout: 30 seconds
Output: snapshots/311_requests_YYYYMMDDTHHMMSSZ.json + snapshots/311_requests_latest.json
Error Handling: Exits with code 1 on failure, logs to stderr

File: /mnt/project/scripts/rebuild_site.py
Environment: Python 3.11 (invoked by GitHub Actions or local)
Purpose: Load snapshots + generate dashboard HTML + GeoJSON layers
Inputs: snapshots/311_requests_latest.json, snapshots/columbus_scooters_*.csv
Output: docs/index.html, docs/gbfs_vehicles.geojson, docs/311_complaints.geojson
Dependencies: Standard library only (json, csv, pathlib, datetime)
Deployment: GitHub Pages automatic (GitHub Actions handles push)

DATA FLOW
=========

311 Data:
  Pull: https://maps2.columbus.gov/arcgis/rest/services/Applications/ServiceRequests/MapServer/0/query
  Fetch: pull_311.py (via pull-311-data.yml, hourly)
  Store: snapshots/311_requests_YYYYMMDDTHHMMSSZ.json (committed to repo)
  Consume: rebuild_site.py
  Output: docs/index.html, docs/311_complaints.geojson
  Deploy: GitHub Pages (automatic)

GBFS Data:
  Pull: Veo (https://cluster-prod.veoride.com/api/shares/name/cbs/gbfs/...)
         Spin (https://mds.bird.co/gbfs/v2/public/provider/spin/columbus/...)
  Fetch: Veo_Spin_CBS_GBFS_Extract.ipynb (via pull-gbfs-data.yml, 2x daily)
  Store: snapshots/columbus_scooters_YYYYMMDDTHHMMSSZ.csv (committed to repo)
  Consume: rebuild_site.py
  Output: docs/index.html, docs/gbfs_vehicles.geojson
  Deploy: GitHub Pages (automatic)

SCHEDULE
========

311 Data:
  Frequency: Every hour at :00
  Cron: 0 * * * *
  UTC times: 00:00, 01:00, 02:00, ..., 23:00

GBFS Data:
  Frequency: 2x daily
  Cron: 0 8 * * * (8am UTC)
  Cron: 0 20 * * * (8pm UTC)
  UTC times: 08:00 and 20:00 every day

Rebuild:
  Frequency: After each 311 or GBFS pull
  Trigger: workflow_call (internal GitHub event, not HTTP)
  Latency: ~1-2 minutes from data fetch to site live

ENVIRONMENT VARIABLES
=====================

None required. All workflows use hardcoded endpoints (public APIs, no auth).

Optional for local testing:
  - GITHUB_SHA (auto-set by Actions, can be overridden for testing)

FAILURE MODES
=============

If 311 fetch fails:
  - Workflow exits with code 1
  - Snapshot NOT committed
  - Error logged to GitHub Actions log
  - Rebuild NOT triggered
  - Site continues showing stale 311 data

If GBFS fetch fails:
  - Papermill logs error
  - Snapshot NOT committed
  - Error logged to GitHub Actions log
  - Rebuild NOT triggered
  - Site continues showing stale GBFS data

If rebuild fails:
  - Site NOT updated
  - Error logged to GitHub Actions log
  - Previous version remains live on GitHub Pages
